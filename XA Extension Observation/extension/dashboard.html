DIAGNOSTIC CAPTURE

Collection begins at the end of the log on each connection. Brave emits only supported diagnostic events; missing records do not prove inactivity. This is not a complete network capture.

Brave’s source log can contain sensitive URLs and API arguments even when the details checkbox is off. Logging continues until Brave is fully exited and launched normally. A shared process log cannot distinguish identical extension IDs across open profiles.

One-time Windows companion setup

The optional companion needs Node.js 20.11+. In the project folder, run the following PowerShell command using this monitor’s ID:

Then exit Brave fully and run .\native\Start-BraveLogging.ps1. Reopen Observatory and click Connect runtime log. The browser will request the optional native messaging permission. Setup does not change other extensions.
Use -ProfileDirectory 'Profile 1' with the launch script for another profile. The source log is stored in native\runtime-logs; the browser’s diagnostic database can also grow while logging is enabled. See README for shutdown and cleanup instructions.

      

      

        

          
Errors & unexpected refreshes
Navigation monitoring is off.

          
Enable the browser-wide navigation timeline, then select a problem tab for detailed errors, request failures, and reload initiators. Records survive page reloads. No companion is required for tab capture.
Capture uses Brave’s debugging permission and banner, can affect timing, and may be interrupted by DevTools. At most five normal HTTP/HTTPS tabs can be captured. Separately running frames/workers and browser UI are not fully covered. Pausing stops captures; reattach explicitly after resuming.
Reload buttons immediately reload the selected tab and may discard unsaved page input. Otherwise this monitor never reloads a page. Normal versus hard reload cannot be inferred from a generic reload event.
Structured URLs omit credentials, query strings and fragments. Console text, exception messages and native process logs can contain sensitive data. Records stay local and are included in JSON export. Enable diagnostics and connect Runtime calls to also collect browser-process warnings/errors from the companion.

STATIC DECLARATIONS
Import extension manifests
Add declared commands, suggested Windows shortcuts, content scripts, optional permissions, and background entry points.
Choose your Brave profile’s Extensions folder for a bulk import. Only matching manifest.json files are read. Files must match an installed extension ID and version.
Default Windows location: %LOCALAPPDATA%\BraveSoftware\Brave-Browser\User Data\Default\Extensions. For another profile, find its Profile Path at brave://version.
For an unpacked extension, select it in the inventory and use “Import manifest” in its Commands tab. Imports are static; reimport after an update or a same-version source change.

          
MONITOR DESIGN
Local by default
  • managementReads extension inventory and lifecycle events. The API permission also allows management; this application has no enable, disable, or uninstall actions.
  • storageKeeps inventory, imports, up to 2,000 lifecycle events / 3 MB and 1,000 runtime events / 2 MB, plus 1,000 diagnostic records / 1 MB. Oldest records are discarded at either limit.
  • alarmsReconciles inventory approximately every minute while Brave is running. Browser scheduling can delay scans.
  • nativeMessagingOptional permission requested when you connect the local diagnostic log companion.
  • tabs / navigationOptional permissions for tab selection and the navigation timeline.
  • debuggerDeclared at installation. Detailed capture starts when you select a tab and click Capture selected tab.
No host access, injected content scripts, traffic interception, remote code, or analytics. Exported JSON includes retained runtime records and captured arguments when enabled.
